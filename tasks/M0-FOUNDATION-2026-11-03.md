状态：进行中。范围对应 `manifest.json` 的 M0-REBUILD-01 和 M0-REBUILD-02；M0 Gate 尚未通过。此文件是近期任务的工作计划，不是实现或通过证明。

## 目标与边界

为后续合成数据纵切建立可测试的后端基础：授权目录中识别多个项目（含非 Git），项目身份和记忆隔离，事实有来源，观点与反馈可追溯、可修订。研究外发、模型调用和预算分别受控；用户可以暂停或撤权。项目修改、命令和实验须由用户审阅具体方案并明确发起，观察许可不包含执行许可。当前只用项目内合成数据，不访问真实私人目录、真实项目或模型服务。

底层优先：项目/长期记录、工作项和单次执行分离；事实、推断、用户反馈和观点版本分离。借鉴 DeepSeek 原型的状态与执行分离，不引入完整工单系统，也不把模型、后台 worker 或看门狗视为安全边界。跨平台共享合同与核心逻辑，路径和系统能力通过平台适配层处理；不可假定 Windows 已通过验证。

## 合同复核与冲突处理

1. `AGENTS.md`、安全合同、接口合同和 QA Gate 为约束；重建计划和 MVP 产品合同描述当前目标。旧设计和历史证据不代表当前实现或通过。
2. 旧合同允许某些低风险动作自动执行；当前产品合同对项目改动、命令和实验要求具体方案与明确发起。本次取更严格的限制；后端不得因 L0/L1 分类自动获得这些权限。研究许可、执行许可及外发许可互不替代。
3. 旧 E2E 卡片和执行流程属于历史验收语境。M1→M2 仍须按 `docs/06-QA-BENCHMARK.md` 执行 E2E-01～12 的适用项，逐项提供证据或准确说明不适用/无法运行；不能因重建或产品定位变化直接删除门槛。任何不适用的判定需有理由与审查记录。
4. `docs/04-CONTRACTS.md` 的 schema、状态机、policy 和 SQLite 迁移要求仍有效；产品新增的项目发现、观点和版本需求需在其上增补，不能降低既有安全语义。合同变更必须串行评审。

## 合成验收草案

- 正例：测试创建隔离的合成根目录，含 Git 项目 A、非 Git 项目 B；识别身份并持久化带来源的事实，重启可恢复；观点 v1、用户反馈和基于新证据的 v2 关联同一项目且保留历史。
- 路径：拒绝 `..`、超出授权根的路径和指向根外的符号链接；测试只使用临时合成目录。跨平台 realpath、大小写、盘符及链接行为分别验证，不能用 macOS 的结果代表 Windows。
- 隔离：查询项目 A 不能返回 B 的事实、来源、记忆和观点；未知或不明确归属不能擅自归入某项目。
- 来源：缺失、失效或不可验证的来源不能升级为已证实事实；事实与推断分开保存。
- 撤权/暂停：任务中断后停止后续读取；重启后不得自动恢复已撤销许可；可恢复的工作须重新核验当前授权。失败不伪装成成功。
- 外发/副作用：默认零模型、零网络、零真实执行；伪造前端风险、审批或完成状态不能越过服务端 policy；模拟执行器计数为零。
- 持久化：重复请求不会重复产生副作用；迁移重复运行安全；注入失败、事务中断及重启后状态一致，审计记录不能更新或删除。

这些是待实现的验收条件，并非已执行测试。应在实现时为每条建立具体可复现用例，并将脱敏输出放在 `handoff/EVIDENCE/`。
