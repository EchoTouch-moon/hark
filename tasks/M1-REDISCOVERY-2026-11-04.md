# M1：合成项目重新发现闭环

状态：**计划完成，开发未开始**。M0 基础合同 Gate 已在 `46ab047` 通过；M1 Gate 未通过。近期只建设用户可体验的合成只读纵切，实施状态以 `DEVELOPMENT-PROGRESS.md` 为准。

## 用户可验收的结果

在明确标识的合成演示中，用户启动项目盘点，看到临时测试根下的 Git 项目 A 和非 Git 项目 B；进入一个项目查看有出处的目标、成果、待办和一条观点，追问或质疑后看到反馈和保留旧版的修订；重启后仍能回看。未识别或归属不明确的内容单独展示，不能猜测归属。界面包含基本炉心/火焰视觉标识和全局盘点、项目对话；无需复杂动效。

M1 对话和观点可先用确定性的合成规则或 mock，并在页面清楚标注；必须将输入材料、推断、用户反馈和修订依据区分显示。不得把预置回答声称为模型真实理解、外部研究或对用户项目的真实发现。没有证据时返回未知/空态；用户反馈本身不自动变成事实或反证。观点版本 v2 应说明变化原因和引用，保留 v1，不能凭空生成新的可信事实。

## 安全与范围

- 只能读取由测试/演示代码创建且显式登记的隔离合成目录及其模拟文件；不得接受任意用户路径、家目录扫描或真实项目。目录预检不等于安全打开；需要覆盖越界、符号链接、替换竞态等实际读取边界，并在不能证明安全时拒绝读取。不要对合成 Git 项目运行 Git 或项目中的命令；其标记和内容由 fixture 构造。
- 源授权与暂停、撤销、来源失效须在每次读取和使用既有记忆时检查；中途撤权停止后续读取，重启不得恢复撤销的权限。来源缺失、过期、归属不明或超出范围要失败关闭。不同项目的材料、证据、对话和观点严格隔离。
- 零真实模型、网络研究、外发、命令执行及真实 connector；不修改合成项目内容。Hearth 自身在隔离位置持久化自己的演示数据库与必要状态，不把这种存储误称为对项目的副作用。fixture 内容视作不可信数据，不作为指令执行。
- 现有执行动作保持关闭。只有准备接入执行能力时，才要求可信 store/身份认证、事务内一次性 grant 占用、结构化独立 verifier 和数据库约束等执行门禁；这不是实现合成只读发现/记忆的前置。真实 connector 启用仍须先通过 `docs/05-SECURITY.md` 的 P0 Gate，并取得明确适用授权。

## 子任务和依赖

1. **M1-A｜合成目录发现**（首个可认领任务）：构造隔离目录、Git/非 Git 两个项目与一个不确定归属样本；设计明确的可重复身份映射，持久化发现与归属状态，重启找回；支持取消/暂停/撤权，实际读取前及使用记录时复核。主 Agent 负责发现、路径和授权核心；外部 Agent 可独占 fixture 构造和非安全敏感测试文件，主 Agent 审查。断言两项目被识别、身份不重复、同名或嵌套等未知归属不乱归、重启一致、边界/撤权失败关闭；不宣称发现真实项目。
2. **M1-B｜有来源的理解与记忆**（依赖 A）：从合成材料提取目标、成果和未完成项；每项附项目与来源标识，事实、推断、未知分开；复用现有 Chronicle/授权/epoch 约束，验证重启、隔离、失效和重复摄取。项目读取由服务端限制 scope，GET 不产生写入副作用；规则仅覆盖声明的 fixture 形式，无法识别时保持未知。
3. **M1-C｜观点、追问与修订**（依赖 B）：一条基于可验证合成来源的观点，带不确定性；用户追问或质疑可保存反馈并生成含修订原因与证据引用的 v2，保留 v1；避免将用户质疑当成事实证伪。测试跨项目注入、来源失效、并发/重复修订、重启和无新证据的真实空态。首版明确为合成/mock，不宣称真实智能或价值已验证。
4. **M1-D｜最小交互体验**（依赖 C）：简洁中文对话页，含炉心标识、合成模式提示、全局盘点、项目选择、来源与 v1/v2/反馈、加载/空态/错误及重启恢复；不实现复杂动效和实际执行。浏览器场景应验证真实渲染、项目切换隔离、追问/反馈和服务不可用状态，截图与运行证据如实留存。

每项开始时在看板写负责人和状态；验收后逐项勾选并链接命令、平台、提交与脱敏证据。代码合同、迁移及安全边界由主 Agent 串行处理；并行工作最多两个 Agent，文件范围不重叠。
