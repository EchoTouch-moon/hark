## 1. 组 A：G1-A 门禁与恢复故障矩阵

### 1.1 崩溃点枚举（基于 `orchestrator.ts` 实际行号）

`process()` 的写入顺序如下（`packages/core/src/orchestration/orchestrator.ts`，`e470436`）：

| 段 | 行 | 动作 |
|---|---|---|
| P1 | `:248` | `transitionRun(→ executing)` |
| P2 | `:250` 起 | `executor.execute(...)` 真正跑动作 |
| P3 | `:281` | `transitionRun(→ verifying)` |
| P4 | **`:287-296`** | `transitionRun(→ completed)` ← **先标完成** |
| P5 | **`:297`** | `addEvidence(...)` ← **后写证据** |
| P6 | **`:306`** | `updateCard(→ completed)` |

`recoverInterrupted()` 只扫描 `executing` 与 `verifying`（`:181`）。

于是可以枚举出六个崩溃点，每个都要有独立断言：

| ID | 崩溃位置 | 崩溃后磁盘状态 | 当前恢复行为（静态推断） | 判定为 PASS 的条件 |
|---|---|---|---|---|
| **C1** | `createRun` 之后、`process` 开始前（run=queued） | run 存在、无卡片状态变更 | `queued` 不在扫描范围 → 停住 | 重启后该 run 要么被明确标为"未启动、可安全删除"，要么被恢复流程接管；**不得静默永久 queued** |
| **C2** | `:248` 之后、`executor.execute` 前（executing） | run=executing，无产物 | 扫描命中 → 重算产物 → 失败则 `pending_verification` | 不得自动重跑动作；落到待人工确认 |
| **C3** | `:281` 之后、`:287` 前（verifying） | 有产物、未置完成 | 扫描命中 → 重算 → pass 则 completed | 与 C2 相同，且不重复执行 |
| **C4** | **`:296` 与 `:297` 之间**（completed 但无证据） | run=completed、**evidence 表无该 run 的行** | **扫描不命中（completed ∉ 扫描集）→ 永不修复** | 必须能检出"completed 但缺 evidence"的不一致；当前预期 **FAIL** |
| **C5** | `:297` 与 `:306` 之间 | run=completed、有证据、card 未完成 | 扫描不命中 | 重启后 card 与 run 状态收敛一致，或明确报出不一致 |
| **C6** | deny 分支 `:236` 与 `:242` 之间 | run=blocked、card 未 blocked | 扫描不命中 | 同上；且不得把 blocked 当成"可执行" |

**C4 是本轮唯一有源码级确定性的判断**：`completed` 早于 `addEvidence`，而恢复只扫 `executing/verifying` —— 这不是"可能不可靠"，是"确定不会修"。是否可被外部触发、是否造成用户可见损害，仍标 `UNVERIFIED`。

**注入方式（设计）**：不改生产代码的前提下，用 `clock`/`storage` 的测试替身在指定行后抛错；或在 `addEvidence` 前插入一次性失败钩子。**C4 若要可测，需要先有一个"注入点"，这属于改动——本轮只冻结用例，不实现注入点。**

### 1.2 模式门禁矩阵

门禁必须按**运行模式**而不是按能力判定（R9 A2）。四个入口 × 三种模式，逐格给期望：

| 入口 | `demo` | `real` | `unknown`（未识别/失效） |
|---|---|---|---|
| `executeCard`（`runs.ts` 直达） | 允许（产物标 mock） | **拒绝，零副作用** | **拒绝，零副作用** |
| `recoverInterrupted`（启动） | 允许（重算 mock 产物） | 允许**核验**，但不得启动新执行 | 允许核验，不得启动新执行 |
| `GET /threads/:id/proactive` | 允许读 | 允许读，**且零写入** | 允许读，零写入 |
| `POST /approvals/:runId` | 允许 | **拒绝** | **拒绝** |

每格的断言统一为三条：
1. executor 调用次数 = 0（real/unknown 栏）；
2. `runs` / `run_steps` / `evidence` / `cards` 四张表的行数与内容在请求前后完全相同；
3. 审计日志新增恰好一条拒绝记录，且不含路径/正文。

**为什么必须按模式而非能力**：`evaluatePolicy` 的 ctx 里没有 `demoMode`（R9 §1.3），所以"授权通过但模式不允许"这一格今天无法表达。矩阵的价值就是把这一格显式化。

### 1.3 作用域矩阵

| 场景 | 期望 |
|---|---|
| 只授权项目 A 的线程请求 B 的卡片 | 拒绝；且返回体不含 B 的任何标识 |
| 全局 scope 下 `listCards` | 不得跨项目聚合，或必须显式带 projectId |

**出口（组 A）**：C1–C6 + 4×3 门禁格 + 4 条作用域，每格一条可执行断言；未执行的格统一标 `NOT_RUN`，不因"设计完整"记为 PASS。

## 2. 组 B：心智与克制实验

### 2.1 五级漏斗（分母必须分开记）

R10 §5 要求区分"卡片创建"与"每项目过去 24h 真实呈现"。落到可测定义：

```text
candidate   —— 规则或来源产出的候选（分母 1）
  ↓ 资格判定（服务端可证：新证据 / GoalRevision 关联 / 冷却 / 配额）
eligibility —— eligible | not_eligible(reasonCode)
  ↓ 服务端选择（同一时刻只允许一条主观点）
claim       —— 被选中要展示的那一条
  ↓ 客户端回执（真实渲染完成）
presented   —— 用户屏幕上出现过
  ↓ 用户动作
feedback    —— 采纳 / 修改 / 搁置 / 反驳
```

四个指标，各自独立统计，**不得互相替代**：

| 指标 | 分母 | 用途 |
|---|---|---|
| 静默率 | candidate | 是否"没事就安静" |
| 漏报率 | 有人工标注为"值得看"的 candidate | 该说没说 |
| 误报率 | presented | 说了不值得说 |
| 打扰成本 | presented / 天 / 项目 | 是否越界 |

### 2.2 配额口径必须先定死，否则实验无效

现有代码里有两个不同口径，**绝不能混用**：

- `discovery.ts:76-79`：**全局、自然日**、最近 200 条卡片**创建**数；
- G0-05 §5 第 4 条：**同一项目、24 小时**内主动**呈现**≤1 条。

两者在三个维度上不同：窗口（自然日 vs 滑动 24h）、作用域（全局 vs 项目）、计数对象（创建 vs 呈现）。

**R11 决议（研究默认，非工程值）**：实验必须**两个口径都实现并对比**，因为这是唯一能回答"哪种口径更符合用户感受"的方式。具体取哪个，等实验数据，不先冻结。

### 2.3 四类必测场景（每组一对正反例）

| 组 | 正例（应展示） | 反例（应静默） | 观察点 |
|---|---|---|---|
| **N1 新证据** | 出现了此前未呈现过的证据 | 证据与上次完全相同，仅时间变了 | 差集口径是否正确 |
| **N2 目标关联** | 与当前 GoalRevision 有可解释关联，`whyNow` 能写出 | 与目标无关但"看起来重要" | 有没有 fake whyNow |
| **N3 时效** | 新证据新鲜 | 源 stale / epoch reset | stale 时是否静默且**说明**原因，而非当成"没事" |
| **N4 跨项目** | 只谈 A | A 的候选里混入 B 的证据 | 任一字段不得出现 B 的 id/标题/文件名 |

补充两条边界，来自 R6/R7 的争论：

- **N5 用户正在输入**：属于客户端状态，不进服务端纯函数；实验只验"服务端给出的 eligibility 在输入前后不变"。
- **N6 配额边界**：自然日 23:59 → 次日 00:01 的跨天行为，与滑动 24h 的行为必须分别记录。

### 2.4 负例必须留痕，但不留正文

按 R7/R10 收敛的形状，每个 candidate 落一行：

```
{ projectId, candidateHash(受密钥保护), ruleRefs, ruleVersion,
  triggerKind, disposition, reasonCode, decidedAt, boundedCounts }
```

**不落**：候选正文、查询词、绝对路径、URL、来源全文、模型输出。

**断言**：给定 N 条合成事件，disposition 行数 = N（含被过滤的）；正则扫描全表，不得命中路径分隔符、`http`、或 fixture 正文片段。

1. **不运行**真实模型、公网检索、真实用户项目、任何执行器；全部用合成 fixture。
