# M1-A 合成发现合同（A-C1）

状态：A-C1 设计合同经独立上下文复审，可作为 A-C2 输入；不是目录发现器、安全打开实现或真实 connector。范围限于由测试/演示代码创建、内部登记的隔离合成根；任何外部目录、模型、网络、执行器均不接入。适用 `AGENTS.md`、`docs/05-SECURITY.md`、`docs/04-CONTRACTS.md` 及 M1 计划。

## 信任与权限

- 合成根由服务内部创建并登记为不透明 `rootId` 和根实例 `rootEpoch`；客户端不能提供或注册任意本机路径，也不能靠自称的 `principalId` 授权。根的内部凭据与根目录位置不在公开结果中。不得将 fixture 模式连接真实项目，也不得把其标识提升为正式身份认证。
- 新项目尚不存在时，现有 `observation_grants` 按项目绑定，不能用不存在的 project grant 来授权根枚举。因此根枚举须有独立、服务端创建的**合成根枚举授权**；它只适用于登记的合成根，不授予任意文件内容或正式项目观察权限。已确认的合成项目只有在为该项目建立 scope、并复核已有观察 grant 后才可使用来源和记忆；不得用根权限代替项目 grant。此授权目前只规定语义，尚无实现或 migration。
- 每次枚举、打开、使用候选缓存及记忆时检查服务端当前权限/暂停/撤销/过期与 rootEpoch；项目内容及记忆另按项目检查 grant、活动状态和来源 epoch。授权关闭、无效时钟或状态无法核实则失败关闭；进行中任务在下一次读取前检查停止，不能声称已经撤回已发生的读取。

## 候选与身份

- 枚举只在登记的合成根中进行，输入输出使用受限相对路径，不公开主机绝对路径；明确界定可枚举范围和深度，拒绝 `..`、空组件、绝对路径、反斜杠、NUL、符号链接和任何无法安全判断的组件。路径大小写、盘符与链接差异需在对应平台核验。
- 候选至少携带服务端分配的稳定不透明候选 ID、rootId、rootEpoch、相对路径、类型（模拟 Git 标记/非 Git/未知）、归属状态（已确认/待确认）与检查时间；结果标识为 synthetic。路径或名称相同不证明同一项目。普通模拟标记只表示合成场景，不能声称有效 Git 仓库或调用 Git。
- 在同一根实例且身份绑定未改变的情况下，重复发现和重启必须返回同一 ID；ID 由持久化绑定保证，不依赖显示名。目录移动、重建、不可区分的替换或根实例变化不能仅凭路径继承身份；保守地标记待确认、失效旧绑定并阻止旧内容被当作新目录事实。根实例 token 与真实文件对象的绑定机制须由实现验证；未经验证的替换或竞态不得被视为可识别。
- 同名、嵌套、重叠或缺少归属证据的候选默认待确认，禁止自动合并或归入其他项目。待确认候选不自动获得项目 grant、来源或观点。任何身份变更和授权创建须由服务端在事务边界内校验；仅作为合成演示，不实现真实用户身份认证。

## 读取与状态

- `inspectPathCandidate` 是预检，不能保证检查后打开安全。实际打开必须使用经审查、能抵御目录/文件替换的系统能力，且在打开前后核验当前根绑定和授权；如果 Node 或平台无法证明竞态安全，该路径返回不可用并记录阻塞，不回退到普通路径打开。读取量、文件类型、大小与层级有明确上限；项目文本始终是不可信数据，不执行其中内容。
- **A-C2 实施选择**：当前 Node 路径 API 不提供本合同所需的完整相对目录句柄能力。实现先提供受审的 `FixtureRootHandle` 适配器：只能从内部新建的受控临时根取得根句柄；`list(handle, relativeComponents)` 与 `read(handle, relativeComponents, maxBytes)` 都只接受经过校验的单段组件，不返回或接受对外绝对路径。macOS 方向是由主 Agent 审查的原生目录句柄相对操作（逐层 `openat`/`fstat`、禁止跟随链接），并以真实目录替换、重命名和链接竞争验证；具体系统能力与竞争语义仍须实际验证。Windows 没有已验证适配器时返回 `unavailable`，不得退回 `realpath` + 普通打开。持有目录句柄本身不证明所有目录替换竞态安全：须证明打开对象仍属于所登记根的允许范围，证明失败就停止读取。适配器的可行性及原生依赖、构建和跨平台支持是 A-C2 的前置风险，不宣称已经解决。仅凭元数据或静态清单不能冒充已从合成目录读取内容。
- 进程重启不能序列化文件句柄：仅当可从服务端控制的受信任锚点安全重新取得根句柄，并验证持久化的根实例绑定及当前授权时才恢复；否则返回 `unavailable`，不能以路径相同视作同一根。实际系统约束使恢复无法完成时，必须记录 BLOCKED，不以重新生成 ID 充当恢复成功。
- 句柄不透明、不可序列化，只由服务端当前操作持有；操作完成、取消或授权撤销后即失效并释放，不可供后续操作复用。异步调用可以发生在该操作的受控生命周期内，但每次适配器调用前后仍需复核授权、句柄有效性和对象身份；数据库授权快照一致性与文件系统对象身份检查是两项独立保证，前者不能替代后者。
- **枚举授权持久合同**：将来由主 Agent 串行迁移定义服务端记录，至少含 `rootId`、`rootEpoch`、合成模式固定内部 owner、`enabled`、`paused`、`expiresAt`、`revokedAt`、根实例绑定和记录版本；根实例绑定不得作为对外路径披露。服务端在创建并取得根句柄后发行，禁止从客户端接受签发字段；状态变更仅允许 active→paused→active、active/paused→revoked，撤销不可逆，根重建必须递增 epoch 并撤销旧绑定。`checkFixtureRootAccess(rootId, rootEpoch, operation, now)` 由服务端从持久记录及当前句柄验证，不信任调用方提供授权结果。每次检查在事务中一致读取 epoch 和授权版本，枚举/读取前后再次核验；检查失败即停止使用新结果。该接口是拟实现合同，当前未落地，且单次校验不代表外部 I/O 和数据库事务原子。
- 可公开状态：`available`（仅表示本次安全检查与授权允许合成使用）、`needs_confirmation`、`unavailable`、`cancelled`。未注册、撤权、暂停、超时、来源失效或读取不确定时不能以成功空列表掩盖错误；不返回跨项目内容或底层绝对路径。只读 GET 不触发扫描或写入；发现/重新扫描由显式操作触发，Hearth 自身数据库可保存合成状态。
- 撤权、暂停、过期、失效或安全能力不足映射 `unavailable`；用户显式取消本次任务映射 `cancelled`。`needs_confirmation` 只允许在有效的合成根枚举授权内返回最小候选信息，不授予项目内容/记忆访问；项目授权缺失时不附带项目资料。
- A-C2 在暴露调用接口前应将这四种状态定义为受严格校验的类型化结果；D-C0 的展示合同必须引用同一含义，不能自行将拒绝转换为成功空态。
- 持久化需记录版本化 schema、唯一约束和事务边界；重复请求不产生重复绑定。重启后加载当前根实例与授权再恢复，不能凭历史结果自动重授权。任何 migration 必须由主 Agent 串行实现，升级/重放/失败回滚有测试。

## A-C2 必测及完成条件

1. 由测试创建合成 Git 标记项目、非 Git 项目、同名/嵌套和归属未知样本；重复发现、重启、冲突、根实例变化以及新授权都验证预期身份和状态。
2. 对根外路径、符号链接、组件替换竞态、未知根与越权 scope 实际运行负例；不能实现安全读取的环境标 BLOCKED，不声称通过。
3. 枚举及项目读取分别测试过期、撤销、暂停、无效时钟、中途停止和重启；项目 A 的来源、事实、观点不得通过项目 B 返回。不能只靠 mock 掉真实检查证明安全。
4. 成功与失败均记录脱敏证据，断言无真实网络/模型/命令/执行器调用，未修改合成项目；记录 macOS/Windows 具体平台与能力。fixture 模式不能推导真实目录可用或 P0 Gate 已通过。
