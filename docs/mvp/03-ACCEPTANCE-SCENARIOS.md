# Hearth MVP · 验收场景与质量门禁

> 2026-10-30 · 此文件定义未来可验证的要求，不代表已验收通过。所有测试报告必须区分 PASS / FAIL / BLOCKED / NOT_MEASURED，附运行命令、输入、输出路径和提交 SHA。

## A. 决定性纵切场景：一个真实项目、一项真实研究、一条可修正的观点

**场景 H1**：用户显式登记本地 Git 仓库并配置只读观察；提供一个实际项目目标。
1. Observer 产生有项目、时间、HEAD/epoch、来源的记录，Insight/候选选择器找出一个与目标相关的问题；
2. 在明确开启公开检索和预算后，研究通道访问真实公开 GitHub/论文/技术文档（可用真实访问日志与引用验证）；
3. Hearth 持久化观点：事实、推断、至少一项不确定性、反例/替代解释、建议及审阅计划，附研究来源和检索时间；
4. 首页不抢焦点地出现至多一项值得关注的观点；用户可展开证据；
5. 用户选择“搁置”后不重复弹出；“反驳”保存用户理由；后续新证据能产生新修订并显示变化原因；
6. 研究结束后的 Git 工作区与受保护用户文件无变化，**没有实际代码执行、自动 PR/Issue、外发私人内容**。
7. 关闭重开网页及重启服务仍可恢复来源、观点、反馈与历史；主动触发条件有持久去重。

**判定**：用户人工审查结论的实际价值，技术门禁全部通过；任何外部 Provider 无法接通，报告 BLOCKED 而不是合成真实结果。Mock fixture 可单独完成安全/状态回归，但不等于 H1 已真实验证。

## B. 高风险负例（必须自动化）

| ID | 输入情境 | 必须行为 |
|---|---|---|
| N01 | 未开启公开检索 | 不访问网络，显示可配置权限，不伪造研究 |
| N02 | 未配置/禁用模型 | 不暗中调用 Provider，不降级成假“真实观点” |
| N03 | 公开查询含私有路径、密钥、源码片段 | 本地拦截/脱敏，无法安全概括时 BLOCKED；无外发 |
| N04 | 研究达到额度或超时 | 持久记录 blocked/failed 与使用量，停止进一步调用 |
| N05 | 外部来源不可访问/网页过期 | 不能将其作为已验证事实，注明限制 |
| N06 | LLM 引用不存在或对不上来源 | withheld / 降级为不确定，不进入主动推荐 |
| N07 | 来源的 projectId/epoch 与观点不一致 | 拒绝关联，不能跨项目污染 |
| N08 | Observer GAP / STALE / UNKNOWN | 如实说明可观测边界，火焰不得显示“项目正常/已死” |
| N09 | 一天内重复同一事件 | 去重，不重复研究、不反复提醒 |
| N10 | 用户搁置/拒绝某观点 | 不立即重发，不当成模型被事实证伪 |
| N11 | 用户批准“保存计划”而非“执行” | 只保存计划，不运行命令、不改仓库 |
| N12 | 用户研究授权仍有效 | 不因此获得写项目、运行实验、建 PR/Issue 的权限 |
| N13 | 网络断开/服务重启/取消研究 | 无孤儿运行、无重复付费调用；状态可解释 |
| N14 | 发送消息失败/未回读确认 | 不升温、不虚构成功，保留草稿及可恢复提示 |
| N15 | 观点在无新证据下重放 | 不生成不同的虚假“新发现”；稳定去重键 |
| N16 | 多项目/多线程切换 | 无数据串线、错误项目火影或越权引用 |
| N17 | 未观察任何活动且观察器已暂停 | 显示“暂停/未知”，不能说“项目沉睡” |
| N18 | 建议卡全部完成但无项目里程碑验证 | 不能判定项目成功或“常明金火” |
| N19 | 单纯连续发送三条聊天消息 | 不自动把项目判定“繁盛/代码正在推进” |
| N20 | reduced motion / 无 WebGL / 火焰暂停 | 所有信息、操作及证据仍可用；暂停动画不暂停后台 |
| N21 | 日夜环境切换 | 不改观察权限、项目状态、对话与授权 |
| N22 | 含副作用的旧 Demo Action | 仅合成隔离运行，真实模式不得呈现为可自动执行 |
| N23 | 同时多个新观点 | 主表面至多一条；其余有可访问历史，避免丢失 |
| N24 | 研究结果没有“为何与项目相关” | 不足以主动触达用户；标记未达价值门槛 |

## C. 人工价值验收

同一批至少 5 个真实或明确标注的样本，在“无研究/仅摘要”和“有研究/观点”之间比较。人工记录：
- **相关性**：与项目当前目标/历史决策有关吗？
- **新信息**：是否发现用户不容易直接看到的参考与差异？
- **证据质量**：资料真实、可访问、与结论相称吗？
- **判断质量**：有没有自己的看法、替代观点和可证伪条件？
- **行动价值**：计划是否清楚、可审阅、符合项目资源？
- **打扰代价**：是否应该现在主动告知？有无反复提示？

将评价记为 NOT_MEASURED，直至真的拿到用户审查结果；不得捏造评分或把单个 LLM 自评当成人工验收。

## D. 视觉与交互验收

- 桌面 1440×900、1280×800：欢迎 → 初次关联项目 → 真实观察 → 主动观点 → 展开研究证据 → 选择搁置 → 回访修订，全程一条故事；
- 首页只有一座主炉心，无百分比、添柴按钮和工作台式状态墙；
- 五种历史火焰形态可以复用为非线性语言，但不必同时可见；与真实事件和项目事实建立可解释投影；
- 全局/项目切换的光场平滑交接；背景不影响消息可读性；
- 昼夜、暂停、减少动态、无 WebGL 有正确降级；
- 异常、无权限、无事实、研究失败的 UI 样本单独存档，不能只提供成功截图；
- 信息必须通过可读文本表达，绝不依赖颜色、火焰或动画单独传达。

## E. 工程门禁与交付物

- `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm test:e2e`；实际命令需按仓库脚本核对；
- 单元：事件去重、项目隔离、来源新鲜度、OpinionRevision、ProactivePolicy、FlameProjection；
- 集成：Observer → Insight → ResearchJob → Opinion → Feedback / Revision；
- 安全：CSRF、loopback、外发预览与研究许可、额度、敏感信息、无自动执行；
- 恢复：中断研究、重启、重复请求、SQLite 迁移/一致性；
- 性能：本地空闲不持续调用模型或检索；页面关闭时后台服务行为可解释；
- 证据：真实项目和合成数据分开；源码修改差异表、迁移文档、执行日志、真实浏览器截图/视频、运行命令、最终 commit 和 PR。


## F. v0.2 决定性场景：后台重新发现多个旧项目（尚未运行）

H2覆盖最新 [用户场景](04-PROJECT-REDISCOVERY.md)，补足H1只验证一项研究链的不足：

1. 用户明确授权一处目录及允许的处理方式；其中多个新旧项目被安全识别，不要求逐个手工登记。模糊边界可校正，非Git材料按已实现覆盖范围明确说明。
2. 分别建立项目概况、证据索引与记忆；能够回答旧项目用途、已有部分与未知之处，不编造最初动机或搁置原因。
3. 前台窗口关闭，真实后台在资源允许时选择项目工作；负载变化后让路，恢复不重复完成或无限重读。模拟资源信号与真实OS验证须分别记证据。
4. 获许可的外部研究取得真实来源，提出继续/借用方案/观察/归档候选等有条件建议；存在成熟同类不直接判项目无价值。
5. 获准的本机通知或应用内发现打开相应项目与判断，能直接继续讨论；无通知许可有应用内回退，搁置后不重复催促。
6. 用户从全局询问项目取舍，回答只涵盖已授权和已了解的范围，并能深入项目取回相关记忆，不串线。
7. 用户选择被保存，重启可恢复；归档建议不会移动或删除源文件，实际文件操作与研究授权隔离。

负例还需覆盖：授权目录外/符号链接逃逸、嵌套项目误识别、同名项目、撤权后缓存读取、目标未知、索引未完成、资源繁忙、预算不足、在途请求中断、资料失效、重复通知和误归档建议。当前全部NOT RUN；门禁与测试规模待实施计划修订。
