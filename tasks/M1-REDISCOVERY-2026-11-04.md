## 用户可验收的结果

在明确标识的合成演示中，用户启动项目盘点，看到预置的模拟 Git 项目 A 和非 Git 项目 B；进入一个项目查看有出处的目标、成果、待办和一条观点，追问或质疑后看到反馈和保留旧版的修订；重启后仍能回看。未识别或归属不明确的内容单独展示，不能猜测归属。界面包含基本炉心/火焰视觉标识和全局盘点、项目对话；无需复杂动效。

M1 对话和观点可先用确定性的合成规则或 mock，并在页面清楚标注；必须将输入材料、推断、用户反馈和修订依据区分显示。不得把预置回答声称为模型真实理解、外部研究或对用户项目的真实发现。没有证据时返回未知/空态；用户反馈本身不自动变成事实或反证。观点版本 v2 应说明变化原因和引用，保留 v1，不能凭空生成新的可信事实。

## 当前阶段的实现原则

在满足现行安全红线和合同的前提下，选择最快形成可验证产品价值的最简单实现。新基础设施、抽象层、迁移、原生依赖或门禁须说明对应哪项当前验收、最简单方案、现有代码为何不能复用及新增复杂性为何必要；不以未来可能需要为由替代当前闭环。复用已验证的 Chronicle、观点存储及权限机制；必要缺陷自主修复。新增重大安全架构、原生依赖、跨阶段门禁或重大重构，先提出最小替代方案、必要性、影响和推荐决策；既不能证明必要性又未经用户批准，不得以之取代产品任务。涉及降低已承诺的安全边界须提出范围变更并由用户裁决。

## 安全与范围

- 当前产品入口只使用程序内预置合成数据，不开放文件系统项目读取、任意用户路径、家目录扫描或真实项目。旧目录读取能力保持隔离，未来重启前须完成越界、符号链接、替换竞态与句柄生命周期等边界验证。不要运行 Git 或项目命令；标记和内容均为合成 fixture。
- 源授权与暂停、撤销、来源失效须在每次读取和使用既有记忆时检查；中途撤权停止后续读取，重启不得恢复撤销的权限。来源缺失、过期、归属不明或超出范围要失败关闭。不同项目的材料、证据、对话和观点严格隔离。
- 零真实模型、网络研究、外发、命令执行及真实 connector；不修改合成项目内容。Hearth 自身在隔离位置持久化自己的演示数据库与必要状态，不把这种存储误称为对项目的副作用。fixture 内容视作不可信数据，不作为指令执行。
- 现有执行动作保持关闭。只有准备接入执行能力时，才要求可信 store/身份认证、事务内一次性 grant 占用、结构化独立 verifier 和数据库约束等执行门禁；这不是实现合成只读发现/记忆的前置。真实 connector 启用仍须先通过 `docs/05-SECURITY.md` 的 P0 Gate，并取得明确适用授权。

3. **M1-C｜观点、追问与修订**（依赖 B）：一条基于可验证合成来源的观点，带不确定性；用户追问或质疑可保存反馈并生成含修订原因与证据引用的 v2，保留 v1；避免将用户质疑当成事实证伪。测试跨项目注入、来源失效、并发/重复修订、重启和无新证据的真实空态。首版明确为合成/mock，不宣称真实智能或价值已验证。

## 统一验收与阶段门槛

- **M1-R01 盘点**：通过受控预置适配器列出模拟 Git 标记项目 A 与非 Git 项目 B；重复运行和重启身份稳定，未知归属不自动归并。不得宣称实际扫描目录。
- **M1-R02 全局与隔离**：全局盘点逐项目检查授权，展示覆盖范围、未分析项与来源；切换项目不能泄漏另一项目的事实、观点或对话。
- **M1-R03 证据缺失**：移除或失效来源时正确表达未知/不可用，不以空列表或编造观点冒充成功；撤权后不得继续展示已失效记忆。
- **M1-R04 反馈与修订**：从 v1 发起追问/质疑，记录反馈并基于明确的修订依据生成 v2，保留 v1 和原因；无依据时如实不修订。
- **M1-R05 重启**：刷新、停止及重启后恢复授权允许范围内的项目、反馈和版本；撤权不被重启恢复。
- **M1-R06 服务失败**：停止合成服务后，页面明确报错，不回退为静态假数据或显示成功。
