# G1-A 线程与聊天作用域临时合同

基线：`bot/hearth-g0-contract@6ef6fe00c90545749f8beef25ac5753e13ccc8e9`；G1-A 尚未通过。用户批准本批 threads/chat 范围，并在现有数据无法证明项目归属时明确选择：**暂时关闭项目内聊天，保留全局对话**。此合同是当前最小 fail-closed 约束，不建立可信项目身份、不替代后续多对多绑定设计。

## 范围与判定

- session 仍是单主体本地会话，既不是项目身份，也不从客户端的 `projectId` 推导授权。此前接受任意 projectId；旧 `threads.project_id` 和消息不具可信项目来源。
- 在可信项目/来源/绑定建立并单独审查前，带非空 `projectId` 的线程创建及列表/详情/主动建议读取、聊天写入与历史读取均返回 `403 PROJECT_CHAT_UNAVAILABLE`。不得以提交项目 ID 自动建线程、绑定、写消息或调用聊天 adapter。
- 旧线程若 `project_id` 非 null，不在全局列表展示其标题或预览，也不能通过详情、聊天、历史或 proactive 绕过项目内关闭；其数据保留原状，不删除、不自动归属。旧 null 线程作为未绑定的全局兼容线程读取和写入，**不因此证明它属于任何项目**。
- 全局场景省略 projectId 或 POST 传 null；已有 null 线程可正常聊天、读历史。未知 thread/session 且不存在遗留消息时允许沿用自动创建全局线程的行为。未知线程若已有孤儿消息，拒绝读取或自动创建，返回 `409 UNBOUND_THREAD_HISTORY` 并保留原记录，不凭 ID 将未知历史提升为全局或项目归属。空历史查询仍只读且不建线程。
- 同时出现的 `threadId` 和 `sessionId` 必须一致；冲突是无效请求，返回 400，禁止静默选择一个 ID。输入在服务端边界做严格校验。
- 失败路径不更改线程、聊天、项目、设置、审计或其他业务表，不调用 Mock 聊天 adapter；所有输入和证据使用合成数据。服务端拒绝不得被前端包装为成功或用项目 Mock 内容覆盖；现有全局聊天和空列表状态须可用。
- 关闭旧项目聊天是可见的保护性限制，不删除历史。将来恢复项目聊天必须另行设计可信项目身份/来源、多对多绑定、旧数据保留和迁移/回滚、撤销和并发；不能直接把旧 project_id 或 null 自动升级为可信绑定。

## 验证与范围限制

先在旧代码执行拒绝测试红灯，再修复并验证双项目不匹配、未知线程/项目、历史绑定线程无项目参数、孤儿消息、别名冲突、全局正常读写以及重启/并发边界。无需 DB migration，不开放执行、研究或模型权限；cards/runs/SSE、Demo reset、真正多项目绑定和完整 G1-A 安全认证不在本批。
