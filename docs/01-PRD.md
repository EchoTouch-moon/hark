# 01｜固定产品需求：本地项目理解与重新发现

2026-10-31整理。依据用户已确认的完整场景与MVP v0.2收拢入口，不新增功能。旧一夜规划可从 `archive/design-exploration-2026-10-31:docs/01-PRD.md` 回溯。

## 目标与使用者

服务积累了许多新旧项目的个人开发者。授权几个目录后，无需逐个整理项目；Agent逐步认识并分项目记住它们。用户想继续时可以重新掌握项目，也能获得有来源的外部参考，判断继续、借鉴已有方案、保留观察或考虑归档。

## 固定核心闭环

1. 安装与范围：在电脑上运行，用户明确授权若干目录及排除范围；许可可暂停或撤销。
2. 发现与理解：授权根内逐个发现新旧项目，不限Git材料；识别边界不确定时保留可修正结果，不猜测为已确认事实。
3. 分项目记忆：项目概况、材料出处、讨论、研究、判断和用户选择按项目隔离；旧目标未知时明说未知，按需取回相关上下文。
4. 对话：支持全局项目盘点和单项目长期讨论，帮助找回以前的思路；范围、覆盖缺口和来源明确。
5. 后台研究：在资源与许可允许时研究项目对应领域、公开工程和成熟实现；电脑忙时让路、空闲时从检查点继续。
6. 判断：结合内部材料和外部证据形成有局限、可反驳、可修订的建议。成熟竞品或长期搁置不能单独证明应放弃。
7. 有意义才提醒：一次聚焦一件值得判断的事，可从应用内发现或获准本机通知进入同一项目讨论；无新价值保持安静。
8. 用户取舍：继续、调整、借鉴、搁置、反驳、归档建议及其理由持久保存，下次能够接着谈。实际搬迁、删除或开发动作独立授权。

完整边界与异常见 [后台项目重新发现](mvp/04-PROJECT-REDISCOVERY.md)；已有正反例见 [验收场景](mvp/03-ACCEPTANCE-SCENARIOS.md)。

## 必须始终成立

- 默认在授权范围内只读；观察、模型外发、公开研究、通知分别有明确许可与预算。
- 不自动改代码、运行项目测试、提交PR、发邮件、搬迁或删除项目。研究许可不等于执行许可。
- 第三方内容是不可信数据；服务端决定权限和执行状态，审计追加写，外部副作用执行前再次读取持久批准并校验。
- 项目间不串记忆、来源或线程；撤权后不得继续读取或外发相关内容。
- 不把Mock、页面动画、格式合格的模型输出或历史测试当真实能力完成证据。
- 用户可暂停/取消；失败、未知、未观察和过期彼此区分，不给项目虚假健康分或进度。

## 两套表达，共用一份产品事实

火焰与记忆表达是历史设计参考，具体形式在重建中重新评估。主交互是自然对话，资料与项目入口按需访问，一句判断按需展开。火焰和折页都不产生项目状态，不引入养成、签到、评分、生活服务或面板系统。

## 当前实现与验收

本次重建移除了旧前后端实现；此前的实现或测试记录均属历史，不能作为当前能力证据。产品合同描述的是目标，不表示功能已经实现。

先用合成目录验证权限、隔离、幂等、撤权和重启，再在另行获得的真实目录、模型和外发授权内验证完整闭环；没有真实证据不能标真实 MVP 通过。现有 M0/M1 门禁不因文件整理自动升级。
