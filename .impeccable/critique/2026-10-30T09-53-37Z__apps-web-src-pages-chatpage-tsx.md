## 优先问题

1. **P1：火的状态越过了事实。** `projectEmber.ts:73` 以卡片全部完成描述阶段成果，`:95` 以三条交流描述代码推进，`:54` 将观察关闭解释成项目搁置。`AppShell.tsx:668` 显示活力条，`:686` 显示百分比；新合同明确取消。实页无登记仓库，空话题却显示“项目刚创立”。移除添柴、百分比、无证据的成长/成果文案；全局默认中性。五种火形可保留为非等级视觉资产，未来从同一份可信 NarrativeState 投影 Story 与 Flame；未知、暂停不能推成休眠。建议 impeccable clarify / distill，G4 接正式投影；修复须同步更改现有错误映射测试。
2. **P1：首个入口不通向首项真实价值。** `ChatPage.tsx:504` 的“介绍我的项目”只填草稿，实际登记在 `ProjectsPage.tsx:165`，位于菜单、项目与话题、管理本地项目之后。明确区分“先聊想法”和“添加本地项目”，说明聊天不会自动授权读取。登记成功后应看到带来源和时间的首次观察，而不是只有阶段变化。建议 impeccable onboard / shape。
3. **P1：对话与真实能力脱节。** `chat.ts` 当前固定 Mock；`threads.ts:59` 的主动建议为 null；分析入口在 `ObserverDetailPage.tsx:354`。现有 UI 尚未承载项目观点和反馈。下一阶段先做稳定项目身份、目标/决定及线程绑定，再建设观点持久化、受限研究及修订；最后接回同一段对话，不能用更丰富的模拟回复冒充能力。建议 impeccable shape。
4. **P2：品牌空间与业务表单不连贯。** `AppShell.tsx:840` 的项目页仍标“项目（调试）”。实际项目页首先是一整块 Git/JUnit 登记表单，话题列表又叫“项目与话题”。正常产品路径去掉调试命名，区分项目和话题。先展示当前项目/截至时间/值得关注的一件事，再按需展开 HEAD、报告和诊断。默认空态、顶部、菜单与话题页重复的生命态说明应收敛。建议 impeccable distill / layout。
5. **P2：回访恢复了消息，却未恢复决策位置。** 线程预览主要是最后一条回复，未将有来源的待决定事项呈现为继续入口。先从已保存记录恢复精确位置；观点/决定模型具备后，再提供有引用的停点和修订摘要。不生成无来源的“我记得”。建议 impeccable shape / harden。

## 用户与情绪旅程

新人：暖白欢迎和可跳过流程降低压力；但介绍项目后收到确定性 Mock，品牌邀请与实际收益之间出现明显落差。回访者：找到历史不等于找回未完决定；活力数字可能使其误解为后台工作。依赖键盘/辅助技术的用户：标签、跳转和减少动态基础存在，但本轮未完成屏幕阅读器、对比度和全键盘验证。菜单超过四项，暂不等同必须删功能；主要问题是把视觉管理、历史、项目混在同层且真实任务较深。

## 推进建议

沿用现有 G1-A → G1-B → G1-C → G2 → G3 → G4 → G5，不另开产品大改线。G1-A 有局部修复证据，但本次未复验联合门禁，旧 G0 表中的 NOT STARTED 也不能直接当作当前实现状态。

1. 当前核心修正：删除已被新合同否定的状态表达、明确项目入口与 Mock；在对应阶段独立验收，不以视觉审查宣称 Gate 通过。
2. G1-B/C：稳定项目身份、目标/决定、类型化来源、观点版本和反馈；先用合成事实验证同一条状态链。
3. G2/G3：仅在单独授权来源、模型、范围与预算后，接通一种真实公开研究入口；形成一份可反驳、有来源且有用的观点。
4. G4：让同一份真实叙事状态驱动对话与火影；一个焦点一条主观点，先露出判断/意义，依据和反馈按需展开，最多两个主动作。
5. G5：真实项目观察 → 受限研究 → 观点 → 人工反馈 → 新证据修订 → 重启恢复；由用户评价相关性、新信息、行动价值与打扰成本。未配置允许受阻，不得写真实闭环 PASS。

增强候选：火形细节、更多转场、金色余辉精修，待闭环成立再投入。未来方向：自动开发、跨设备与更多外部写入，不纳入此次设计审查或当前 MVP。长期项目经历与观点记忆是已确认的核心，不应误列为纯视觉增强。
