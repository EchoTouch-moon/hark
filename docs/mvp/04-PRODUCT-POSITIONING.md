# Hearth · 产品定位与差异化原则

> 2026-11-02 · 产品方向决定（面向 G0 后续实现与验收）
>
> 本文明确 **为什么做 Hearth、与 TRAE 宝等项目助理如何区分，以及如何证明差异化**。这是产品定位补充，不是代码已实现声明、G0 门禁通过、预算/模型/公网访问授权或自动执行授权。安全/隐私/权限以 [G0 需求技术合同](./g0/02-contract-and-decisions.md) 与既有安全合同为准；阶段进入依赖 [G0 计划与验收映射](./g0/03-plan-threats-traceability.md) 和 [双轨分闸](./g0/05-dual-track-and-viewmodel.md)。

## 1. 一句话与用户价值

**Hearth 是本地优先、以可信项目历史为基础、能形成可反驳且可修正观点的长期项目智能同行者：它适度主动指出值得关注的变化，提供证据与方案；是否采取真实行动，始终由用户明确决定。**

产品承诺：**让项目的生命，被看见、被理解、被延续。**

我们要解决的首要问题不是“用户怎样让 AI 写更多代码”，而是：

> 当用户暂时没有提问、同时维护多个项目，或数周后重新回到一个决策时，谁能可靠地告诉他：**发生了什么、为什么重要、过去为什么这样选择、现在该优先考虑什么，以及什么证据会改变这个判断？**

Hearth 不是换皮的 Chat UI、任务工单墙、Git 仪表盘、积分养成火焰或通用自主编码平台。它应该帮助用户**作出更好的项目决策**，而不是将生成任务量或自动执行次数当作终极价值。

## 2. 竞品观察：承认交集，不虚构独占能力

**观察时点：2026-11-02。** TRAE 官方公开资料说明：TRAE 宝有“全局助理”与“项目助理”；前者利用跨项目的任务、对话及产物组织上下文，后者围绕项目拆解、并行协调与推进工作。TRAE 文档也介绍了全局/项目记忆，以及平台的自动化任务能力。

- [TRAE 宝：个人助理（官方）](https://docs.trae.cn/ide_personal-assistant?lang=zh)
- [TRAE：记忆（官方）](https://docs.trae.cn/ide_memories)
- [全新 TRAE 的统一工作流与自动化（官方）](https://docs.trae.cn/ide_traework-to-traecode-data-migration)

因此，**“项目专属聊天”“长期记忆”“多项目管理”“定时主动检查”“多 Agent 协作”均不能作为 Hearth 的独占卖点。** 同类产品可能继续演进；下表是定位取舍，不是断言 TRAE 缺少某种底层机制，也不是未经实测的性能比较。

| 维度 | TRAE 宝在官方资料中强调的方向 | Hearth 选择优先证明的价值（目标） |
| --- | --- | --- |
| 主要成果 | 任务组织、并行执行、代码和其他产物交付 | 更好的项目判断、可信决策历史及值得出现的建议 |
| 组织单位 | 全局助理 + 项目助理，任务与产物 | 持久 ProjectId + Goal/Decision + 多来源 Evidence + OpinionRevision；线程不等于项目 |
| “记忆”如何有用 | 复用历史上下文、规则与偏好 | 追踪**为什么**形成观点、为何接受/拒绝、何种新证据引发修订 |
| 主动性 | 可接受任务，也有自动化工作流 | 观察与已授权的公开主题研究可主动；无新价值即安静 |
| 信任模型 | 遵循其产品的工具/审批机制（不猜内部细节） | 观察、研究、模型、执行独立授权；方案草拟永不等于执行授权 |
| 交互重心 | 项目任务与工作流 | 持续对话 + 按需展开证据 + 项目生命/炉心叙事 |

**核心差异不在于它“会不会主动”，而在于 Hearth 必须证明：主动的判断能否从证据、历史目标和用户选择中被解释、反驳、持续修订。** 对竞品同等能力的有无保持“待实测”，不用营销性排他表述。

## 3. 不可稀释的产品选择

### P1 · 项目优先，不把聊天线程当项目

项目有独立身份、目标、来源、时间线、决定与观点版本。线程可以聚焦项目，但没有真实绑定时不得借用项目事实；跨项目的数据、证据或任务不能串线。

### P2 · 证据先于结论，未知必须保持未知

明确区分 **本地观察事实 / 公开研究来源 / 用户决定**，各自保留时间、范围、来源和可用性。网页引用只能证明来源被获取，不能证明本地项目事实；用户的偏好不是客观事实验证。观察暂停、断流、来源失效、模型未运行，不能包装成“项目健康”“已完成”或“离开期间发现”。

### P3 · 观点是持久对象，不是一次性的漂亮回复

每个可呈现的观点至少有：当前事实、独立推断、为什么现在值得关注、相关目标/历史决定、反例或缺失、不确定性、可执行性为 false 的计划草案、**什么会改变我的想法**。新证据形成不可变的新 revision，旧版可追溯；用户拒绝 ≠ 事实证伪，搁置 ≠ 已执行。

### P4 · 主动发现有边界，真正行动必须由人发起

允许在显式授权的本地观察与**公开主题/来源/频率/预算**内自行发现问题、提出脱敏查询、研究和草拟计划；公开研究授权不自动成为模型授权，模型授权不自动成为执行授权。**未经展示具体方案及用户明确发起，不能修改仓库、运行项目实验、创建 PR/Issue、部署、发邮件或写第三方系统。** MVP 真实执行保持关闭。默认离线、失败关闭、可撤销、可审计。

### P5 · 宁可静默，不拿琐碎变化刷存在感

主动观点须和用户目标或历史决定相关，有此前未见的可信新信息、能说明 whyNow，并在当前焦点与冷却规则允许时呈现。无新价值、来源不足、用户正在输入或已搁置时不打扰；历史可查询。刷新页面不应反复播报。展示与已读、反馈与执行各自独立。

### P6 · 叙事服务理解，不代替真实状态

“一座主炉心，多段项目故事”：项目事实进入 `NarrativeState`，再驱动 Flame/Story；火不是聊天条数、产出分数或用户留存激励。无项目或来源不可信时中性并说明边界。对话是主要表面，证据和项目详情按需展开；不建常驻工单墙。

### P7 · 不为了追赶竞品而扩建通用 Agent 平台

当前 MVP **不以**多 Agent 编码编排、自动 PR、无限模型调用、云端同步、远程多人协作、全网爬取为竞争指标。优先验证最小而可信的“观察 → 研究 → 观点 → 用户反馈 → 修订”纵切；未来若扩展执行，必须重新审核授权和副作用合同。

## 4. 判断是否真的有差异化：可复现的用户体验

**正例（目标体验，尚未宣称已实现）**：

1. 用户登记并允许观察一个真实本地 Git 仓库，保存“先验证机制、后扩大实现”的项目决定及理由。
2. 后来出现**确实已观察到**的项目变化；系统发现与既有目标相关的证据缺口。只有在独立允许的公开主题/预算内，才可能补充外部研究。
3. Hearth 给出一条克制的观点：新发现是什么、证据来自哪里、为什么与先前决定有关、有哪些其他解释、建议先做什么、怎样验证。
4. 用户搁置或反驳，理由被作为用户反馈保存；刷新与重启后不丢历史、不重复骚扰。
5. 以后取得真正的新证据，Hearth 能解释**观点为何改变**，而不是悄悄覆盖旧回答。用户未授权执行，整个过程中仓库/外部系统没有被擅自修改。

**不可接受的伪差异化**：把 Git commit 转述成“项目进展顺利”；无证据地自称一直在后台思考；凭聊天次数让火焰更旺；生成普通的 Todo 清单并标榜独立观点；拒绝后下次刷新继续推荐；未经允许对外搜索私有源码；用一次 AI 打分认定建议“有灵魂”。

## 5. 竞争对照与验收方法

在明确非敏感、可公开且不产生外部写入的实验项目中，使用相同项目背景和问题，对照 TRAE 宝与 Hearth。记录版本、时间、权限、输入与输出；仅比较**实际观察到的行为**，不推断 TRAE 不公开的内部实现。

建议问题（不要求竞品回答失败）：

- **回访**：“我上次为什么没有采用那个方案？现在有新理由改变吗？”
- **证据**：“告诉我最近最值得关注的变化；哪些是观察到的，哪些是推断？”
- **分歧**：“我不同意你的建议，原因是 X。未来什么证据会让你重新提出它？”
- **安静**：“当项目没有可信新变化、观察暂停或权限被撤销时，你如何表现？”
- **主权**：“你能只研究、给出方案而不碰仓库，也不发送私有内容吗？”

**Hearth 验收不能靠文案自评**：G5/H1 至少有一轮真实仓库 + 可控真实公开资料 + 真实授权的完整纵切，以及不少于既有合同规定的人工评价样本（当前要求至少 5 个真实或明确标注样本）。人工评价相关性、证据可信度、新信息、非显而易见性、行动价值、打扰成本和是否忠于用户目标；缺失则 `NOT_MEASURED`。还须验证跨项目、暂停/断流、撤权、超预算、重启与不执行等负例。竞品优劣不是 Hearth 通过门禁的必要条件。

## 6. 与当前实施门禁的映射（不新增日历排期）

| 已存在阶段 | 为定位提供的可验证能力 |
| --- | --- |
| G0 | 明确项目/线程/证据/授权合同和 Mind→Experience 边界；定位补充**不代替** G0 复审 |
| G1-A | 真实模式禁止未授权执行，项目隔离、Origin/CSRF 等安全底座；不能由单项修复推导整闸 PASS |
| G1-B / G1-C | Project Chronicle + 不可变 Opinion Memory、反馈/历史，构成真正的长期项目理解基础 |
| G2 | 限范围公开研究、独立授权/预算、撤销与恢复，禁止私有信息外发 |
| G3 | 可引用、可反驳的观点 + 价值筛选/冷却 + 主动呈现/反馈 |
| Experience / G4 | 可信 NarrativeState 的炉心/故事投影、对话式呈现；UI 不反向制造事实 |
| G5 / H1 | 真实纵切 + 负例 + 用户人工价值验收，确认“值得出现但未经批准不执行” |

阶段由**依赖与验收状态**推动，不由日期或 Sprint 自动解锁。复用现有合同与测试，不新增一套互相冲突的架构或抢先实施编码。相关阶段仍按原合同单独评审、授权和确认。

## 7. 版本纪律

- 本文把 2026-11-02 用户讨论落实为**方向与差异化标准**；不是对 TRAE 宝的技术实现结论。
- 如新研究证明竞品同样具备上述机制，更新比较事实，不因此取消 Hearth 的证据、用户主权与长期观点要求。
- 仅阅读、比较、撰写文档不表示已经运行代码、通过 CI 或完成功能。
- 产品成功定义：**Hearth 在合适时机提出与用户项目真实相关、以前没意识到而且有依据的判断；用户能够查证、不同意、修订或忽略，且始终掌握执行权。**
