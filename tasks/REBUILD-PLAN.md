# Hearth 重建计划

状态：**规划起点；未开始重新实现，也未验证真实闭环。** 本文件整理既有意图，不代表用户已授权真实私人数据访问、真实模型外发或外部发布。

## 核心目标

在用户授权的目录内自动发现多个新旧项目（不限 Git），为每个项目建立独立、可追溯的记忆和理解，并支持全局盘点及项目对话。在真正有价值时，结合公开证据提出可以质疑、反馈和修订的项目观点及建议计划。用户决定是否执行具体计划。

## 唯一优先闭环

1. 用户授权目录及排除范围；在授权内发现多个新旧项目，支持非 Git 材料，识别不确定时由用户校正；隔离项目身份和记忆。
2. 根据可追溯的事实和目标，提出一个值得研究的问题；区分事实与推断。
3. 经单独配置的权限、范围和预算允许后，查询公开资料；记录来源与限制，失败或未授权就如实停止。
4. 呈现一个带证据、反例、局限及可审阅计划的观点；无新价值时不打扰。
5. 支持全局盘点与单项目对话，记录用户反馈；新证据到来时保留历史并修订观点。目标包括资源繁忙时让路、空闲时从检查点恢复，以及经许可的低打扰本机通知。
6. 修改项目、执行命令、实验或其他外部副作用，均须用户审阅具体方案并明确发起，严格受项目安全合同约束。

真实闭环需要真实授权项目、研究来源和用户价值评审；合成数据只能验证机制，不能冒充真实结果。

## 实施顺序

- **0 · 重定目标与合同**：先对照 AGENTS、安全合同和产品合同消解新旧冲突；列出最小范围、可观察行为、安全反例和验收标准。旧文档中的实现、阈值和技术选型只是参考。
- **1 · 本地纵切**：使用多个合成项目实现授权目录发现、独立项目身份、只读事实、来源、观点、反馈及版本记录；验证隔离、停止、持久化和失败语义。
- **2 · 授权研究**：设计查询脱敏、允许范围、预算、取消及审计；得到相应授权后，接通一个公开来源，禁止把隐私内容悄悄外发。
- **3 · 真实体验验收**：仅在用户授权范围内接入一个真实项目，完成观点、反馈和新证据修订；请用户评价相关性与价值，缺权限时明确标记受阻。
- **4 · 增强**：复杂项目关系图、复杂火焰动效、额外通知渠道与自动化均为候选；基本多项目记忆和全局盘点属于核心，不阻塞核心闭环。

各阶段只有合同与适用安全验证通过后才进入下一阶段。`tasks/HEARTH-MVP-REBOOT.md`、`tasks/HEARTH-GATE-CLAIMABLE-BACKLOG.md` 及旧门禁是历史参考，不是当前可直接认领的任务；旧的 M0/M1/M2 Gate 要在合同复核时重新映射，不能因为重建绕过 AGENTS 中的顺序要求。
