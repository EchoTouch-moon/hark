# Hearth MVP · 产品与行为合同

> 版本 v0.1 · 2026-10-30 · 本轮用户确认的意图优先；工程设计是待验提案  
> 安全、隐私和用户对真实副作用的授权优先于叙事文案。

## 1. 产品定义

**Hearth 是具备长期项目理解与项目观点的个人智能同行者。**

它在用户明确允许的本地项目和公开资料范围内观察、研究、思考；当确实有价值时，主动提出一个有依据的判断和可审阅的推进计划。用户对「是否执行真实工作」拥有最后决定权。

**产品承诺：让项目的生命，被看见、被理解、被延续。**

**不是什么：**
- 不是带火焰积分条的 Git Dashboard、签到养成游戏或单纯的聊天皮肤；
- 不是看到一项 Git 变化就说“项目取得进展”的自动总结器；
- 不是拥有永久修改仓库、运行命令、外发私有内容和自行开支预算的全自动编码 Agent；
- 也不应以拟人化语言声称模型具有意识、真实情感、持续思维或从未停止的后台工作。

## 2. 核心人物与真实分工

- **用户**：提出和修订目标；决定信任、登记、观察、检索、预算、优先级及最终行动。
- **Hearth**：守候项目、理解历史、识别问题、检索知识、提出有见解且可修正的观点；诚实呈现依据和边界。
- **项目**：拥有独立身份、目标、事件、决定、研究、里程碑和记忆，不等同于线程或代码仓库。
- **话题/线程**：一次或多次对话的上下文，可关联零、一个或多个项目；项目事实只在明确绑定、符合权限时引用。
- **外部知识**：受预算和访问控制的 GitHub 项目、论文及文档，为观点提供比较和参考，**不能直接证明用户项目已发生变化**。

## 3. 心智循环（核心体验）

```text
授权范围内的感知
  → 与长期目标/项目历史对齐
  → 识别具有研究价值的缺口
  → 在授权预算内主动研究公开资料
  → 形成“事实 / 推断 / 反例 / 观点 / 行动方案”
  → 评估是否值得主动打扰
  → 对话中呈现一个可审阅观点
  → 用户采纳、修改、搁置、反驳或显式批准执行
  → 记录结果、跟进证据、更新观点
```

**关键约束：前三步及受限研究可以预授权自动运行；观点形成不代表获准执行计划。** 不允许“低风险所以自动执行”的例外。

## 4. 主动性的权限分层

| 能力 | MVP 默认 | 获授权后 | 禁止自动发生 |
|---|---|---|---|
| 已登记项目只读观察 | 仅本地、显式登记后 | 可按用户启用的周期采集 | 写仓库、擅自运行测试 |
| 本地确定性洞察 | 已获观察范围内允许 | 去重、来源检查、价值筛选 | 将推断标记为验证 |
| 公共 GitHub/文档/论文检索 | 默认关闭 | 限域、限额、私有内容隔离、可取消 | 将私有路径/源码/密钥作为查询或外发 |
| 模型推理/观点生成 | 默认不自动调用付费远端模型 | 具体 Provider、用途、数据范围、预算、调用上限获预授权后自动生成观点 | 超预算、未知接受方、隐式远端回退 |
| 主动告知 | 页面内低打扰、无事沉默 | 按用户设定节奏出现摘要 | 高频刷卡、捏造后台工作、外部发送通知 |
| 项目改动/命令/实验/PR | 未授权则不可执行 | 展示特定版本计划并由用户**明确发起**，执行仅限批准范围 | 自动开发，即使 Agent 判定“低风险” |
| 发邮件/编辑日历/第三方写入 | 不在 MVP | 后续在具体方案+对象+范围确认下显式发起 | 因“研究已获许可”而自动写入 |

**定义：**研究过程可以保存研究草稿、观点记录、来源元数据到 Hearth 自己的本地数据存储；这属于产品内部记忆，不属于对外执行工作。允许的本地写入应在研究/观察授权中清晰告知。外部仓库、GitHub Issue、邮件、日历、用户文件的写操作不包含在这类许可中。

研究查询也可能泄露信息：先做本地最小化问题陈述与敏感信息过滤，公开查询不得携带私有标识、源码片段或绝对本地路径。无法安全概括就标记 BLOCKED 并询问用户。

## 5. 观点是一等公民

每个 `Project Opinion` 都应该回答：

1. **我发现了什么？** 可定位到具体项目、时间与事实来源。
2. **我怎么看？** 独立推断，明确不确定性及替代解释。
3. **为什么值得你关注？** 与用户目标及历史决定的关系。
4. **我研究过什么？** 搜索词（脱敏）、论文/仓库/文档链接、访问时间、研究限制。
5. **我建议怎么走？** 1 个推荐方案及可选替代方案，风险、预期验证方法。
6. **什么会改变我的想法？** 可证伪条件、未取得的证据。
7. **你决定了什么？** 采纳、修改、搁置或拒绝及用户给出的理由。
8. **后来发生了什么？** 观点版本、再审查及结果，不把未执行写成已实现。

**用户不采纳建议 ≠ 观点被事实证伪。** 观点可被新证据修订、用户偏好约束或直接撤回，但不能悄悄覆盖旧版本。

## 6. 项目生命与火焰：同源但不混义

- **项目生命** = 持续目标 + 经历 + 真实活动 + 决策 + 可继续演进的可能性；不是代码提交速度、聊天次数、成功率。
- **长期故事**：诞生、探索、推进、沉淀、重新出发是非线性叙事章节，不是互斥等级或阶段进度条。
- **近期活动节奏**：只依据可观测的可信事实；“最近没有观察到”必须与“观察被暂停/不可用”区分。
- **瞬时火星**：只由真实的高价值、新近且未重复事件触发；它可以链接到对应的证据与观点。
- **用户交流**：对火焰产生短暂的回应和在场感，但不能把 3 条消息算成项目“繁盛”。
- **重要成果**：只有有范围和验证证据的里程碑可以留下金色余辉；全部建议卡完成 ≠ 整个项目完成。
- **安静与余烬**：时间可以令火势平和，却不清空已记录的成果；缺少数据不能推定休眠。
- **视觉偏好**：手动大小、暂停动态、减少动态效果绝不改变业务或后台任务状态。
- **一座主炉心，多项目故事**：全局默认是中性炉心；只有用户聚焦具体项目且存在可信绑定时，火焰投影该项目的故事。

**删掉**：人为“添柴”按钮、活力百分比、火焰成长激励文案；真实手动扫描叫「立即检查」。保留 PR #5 WebGL+GSAP 视觉资产，但更新其状态驱动。

## 7. 主页面与对话交互

1. 首次进入：暖白/深黑同一空间，短欢迎、可选称呼、明确本地/模型权限边界；能够跳过并快速进入。
2. 核心页面：持续对话占主位，火影在磨砂玻璃之后，简洁安静。项目/历史/设置按需打开；不制造常驻 Dashboard。
3. 项目聚焦：明确当前是“全局”还是“某项目”，并显示观察新鲜度/权限边界的简洁入口。
4. 有事主动：同一焦点最多一条主观点、一张小卡、两个主要选择；其余进入非打扰历史；用户编辑输入时不抢焦点。
5. 观点卡优先展示：**发生了什么 / 我的判断 / 为什么现在值得关注**；事实、来源、反例、研究记录可展开；直接选择“查看依据、稍后、反驳/修改、查看计划”。
6. 用户批准前：计划可被保存、编辑、讨论，不出现会让人误解为“已完成”的执行反馈。MVP 可以把执行动作留在**审批后仍 BLOCKED / 未实现**的状态，不伪造执行结果。
7. 回访：基于持久记录恢复上一段话题和未完决策；只有真实新观察/新研究才说“离开期间发生了……”；后台未运行必须如实说明。
8. 故障：API/Provider/检索/数据源异常时保留已有记录，不使用假数据替补真实结论。离线演示必须清楚标明。
9. 昼夜仅为环境表达，时间不代表用户作息或工作状态；桌面 1440×900 与 1280×800 为当前验收重点，键盘与减少动态效果不可退步。

## 8. MVP 核心范围与不做的事

### Must（真实体验纵切）
- 一个真实用户显式登记的本地 Git 项目；持续只读观察与来源核验，已有 Insight 能力复用；
- 将项目长期目标、决定、观察事实与当前讨论关联，记录来源、时间、缺口；
- 一个从可信事实产生的研究问题（不是随机播报）；在已启用的公网检索通道与额度内主动研究公开 GitHub/论文/文档；
- 观点生成、引用、反例/局限、方案；可持久化、可更新版本；
- 安静式主动呈现，去重/冷却/搁置后不反复打扰；
- 用户对观点反馈（采纳/修改/搁置/反驳）；执行能力与自动研究严格隔离；
- Flame + Story 投影同一份可信 Narrative State；真实项目事件才产生长期语义变化；
- 断流、观察暂停、误关联、失败、超预算、无检索权限的负例；最小可审计日志；
- 至少一轮可重复真实端到端演示和明确未实现能力清单。

### Should（不阻塞核心）
- 观点版本比较、阶段成果余辉的细腻视觉表现；
- 多项目切换与更多历史浏览；
- 用户可设置研究频率、安静时段和本地预算提示；
- 支持用户导出观点与研究摘要。

### Won't（当前 MVP）
- 自动写代码、运行项目测试、自动 PR/Issue、部署、邮件/日历写入；
- 未经单次授权的任务执行或付费模型调用；
- 多人共享/远程暴露、跨设备秘密同步、通用 OS 代理、全网无界自动爬取；
- 实际尚不具备的深度代码审计、云端无限记忆、全自动 Agent 群；
- 把五种火焰状态当作量化评级或把火光动画当作后台任务证明。

## 9. 成功的判断

MVP 的决定性体验不是“火焰很漂亮”，而是用户能够说：

> “Hearth 发现了与我的项目有关、我未主动提问的问题；主动查到了值得参考的公开资料；提出了自己的、可反驳的观点和有用的计划；并且在我批准之前，没有替我执行开发工作。”

建议质量至少人工评阅：**相关性、证据可信度、非显而易见性、行动价值、打扰成本、是否忠于用户目标**。不以模型打分自称通过；详见验收文件。

## 10. 待实测而非假定

- 如何设置初始研究频率/预算、单次检索结果上限；视真实成本与样本评估决定；
- 何种事件可进入“高价值研究候选”，必须人工审阅真实样本；
- 具体联网/模型 Provider 的部署可用性与授权体验；
- 长期记忆多项目扩展与真正自主后续执行，均不阻塞纵切 MVP。

此文档记录的是目标产品合同，**不表示以上能力已在 PR #5 实现**。
