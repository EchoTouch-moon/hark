## 新旧合同的边界与待裁决项

1. **低风险与明确发起**：`docs/05-SECURITY.md` 将 L0 只读 fixture 与 L1 专用目录草稿列为夜间可能允许；`docs/mvp/01-PRODUCT-CONTRACT.md` 对项目改动、命令和实验要求审阅具体方案并明确发起。两者的范围不同：仅项目内合成工作按当前授权进行；任何真实项目改动/命令/实验不得因 L0/L1 自动获准。`docs/04-CONTRACTS.md` 的 `queued→executing: permitted` 只是状态边，不能替代上述准入。L2/L3 的安全底线继续有效。
2. **观察、研究和执行不是同一许可**：有观察授权不代表可向 provider 发送内容、公开检索、产生费用或写项目；收到用户对未来授权真实工作目录的意向也不等于已经明确了可访问的具体范围。禁用私人目录仍不可触碰。
3. **旧 Card/Run E2E 与新产品方向**：`docs/06-QA-BENCHMARK.md` 的 E2E-01～12 是现行质量合同，部分流程描述旧执行导向的 UI；`tasks/REBUILD-PLAN.md` 指出旧实施方案仅为参考。不能直接把旧 E2E 全部删除、全部判通过或把“保存计划”解释为获准执行；M1→M2 前须逐项映射适用行为，给出通过证据或有依据的“不适用/无法运行”记录，并审查这一映射。
4. **接口旧字段与新领域**：`docs/04-CONTRACTS.md` 旧 `Evidence`/Action/Run 面向任务执行；产品要求独立项目记忆及版本化观点。当前新领域结构补充旧合同，不撤销来源、权限、审计、幂等或独立验证要求。旧 `SourceRef.sourceType` 未明确表达普通本地项目来源；正式接口/迁移应给出兼容和显式版本方案，不能把 fixture 或真实 vault 混同为已授权本地项目。
5. **Event 过期语义**：`docs/04-CONTRACTS.md` 的类型将 `expiresAt` 标为可选，但不可变原则同时要求 Event 有 TTL。兼容裁决：保留旧结构解析；作为当前观察事实的预检缺失期限即 withheld，过期、未来时间、无效日期和模型推断也不升级为观察事实。历史记录可以保留；通过时效预检仍只进入“需核验来源”状态。`src/event-freshness.ts` 是纯预检，生产消费方仍须使用可信时钟并重新核验授权、来源、epoch 和真实性；尚无完整生产消费边界。
6. **审批绑定与版本**：接口合同的审批 API 以 run 为路径，而 `ApprovalGrant` 字段以 card/action 为核心绑定；保守合同与验收见 `M0-EXECUTION-AND-E2E-MAPPING.md`。当前没有真实执行入口，不能从状态枚举或 schema 推断审批链已完成。
7. **记录与权限不是同一个证明**：迁移、只追加触发器、幂等键、观点版本和本地结构检查是必要基础；它们不证明用户身份、授权仍然有效、来源存在、陈述得到来源支持或观点有价值。状态展示必须查当前可信状态；历史保留不意味着撤权后可以继续使用。
