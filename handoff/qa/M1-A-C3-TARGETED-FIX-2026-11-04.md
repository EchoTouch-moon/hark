# A-C3 定向修复与剩余阻断

针对 `M1-A-C3-REVIEW-R2-2026-11-04.md`，只使用本机合成临时目录：

1. 根句柄和子句柄改成按对象身份持有的不透明能力；撤权释放根时递归关闭子句柄。新回归先在旧实现复现过期句柄读取另一个根，修复后断言旧句柄不能列目录、打开、读取或关闭新根，复制出来的对象也不能冒充句柄。
2. 读取前将实际打开的候选目录身份与已授权绑定核对；新回归先复现 A 路径替换成 B 后仍返回 available，修复后该具体替换在打开 B 内容前被拒绝。

局部 18 项测试、首轮复现脚本、4 项合成 API 隔离测试、lint、typecheck 和 TypeScript 构建通过；执行结果见 `handoff/EVIDENCE/m1-a-c3-targeted-fixes-2026-11-04.txt`。两项新回归在实现前均实际失败，证据文件记录失败现象。未测试 Windows 或真实项目。

**仍然 BLOCKED**：只核对一次对象身份不能保证读取期间目录持续位于授权根。`node handoff/qa/m1-synthetic-moved-directory.mjs` 用自建合成目录证明，已经打开的目录被移出登记根后，持有的子句柄仍能打开并读取该目录内的合成文件。该脚本复现的是底层句柄能力，不声称已对高层 `readSyntheticFile` 做确定性的并发攻击，也不是安全通过证据。要启用真实目录，必须选择能证明实际读取范围的受控能力并覆盖移动/替换竞态、项目授权和撤权的适用验证；无法证明时继续关闭读取。

这轮修复没有把旧目录适配器接入合成服务，没有通过 A-C3、P0 或 M1→M2 Gate，也没有读取或接入用户真实项目。独立 Gate 复审仍依 `handoff/BLOCKERS.md` 处理。
