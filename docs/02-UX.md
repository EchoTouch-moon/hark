# 02｜前端产品与 UX 详细实现合同

## 视觉定位
原创极简、轻度 editorial 风格，产品名 Hearth。避开 Hark 原视觉资产，不做像素级复刻。不使用大面积玻璃、夸张渐变、炫目动态背景。优先桌面 1440 宽，Mac 原生气质；圆角 10–16px、阴影轻、字重清晰、平稳过渡 160–220ms。

## 导航
左侧折叠导航（240px），顶部 Logo/当前 Workspace；顺序 Home、Chat、Projects、Activity、Settings；中部为内容，右侧在桌面宽屏以 280px Detail Drawer 显示 Evidence/Task Trace。窄屏只保留主面板和详情弹层。路由 `/`, `/chat`, `/projects`, `/projects/:id`, `/activity/:runId`, `/settings`。

## 页面清单 + 布局
### U01 Home
```
┌────────────────┬────────────────────────────────────────────────────┐
│  Hearth        │  Good morning / 今天值得处理的 2 件事             │
│  • Home        │  [ Demo 数据 · 仅本机 ] [ 数据状态 ]              │
│  • Chat        ├────────────────────────────────────────────────────┤
│  • Projects    │  需要你决定                                      │
│  • Activity    │  ┌── Action Card ───────────────────────┐          │
│  • Settings    │  │ CI 没通过 · 为什么现在? 来源/时间    │          │
│                │  │ [查看证据] [开始诊断] [忽略] [稍后]   │          │
│                │  └─────────────────────────────────────┘          │
│                ├────────────────────────────────────────────────────┤
│                │  项目快照 | 最近执行 | 研究下一步（Panel 模板）    │
└────────────────┴────────────────────────────────────────────────────┘
```
卡片最多 3 个“新建议”；超出用「查看全部」，避免认知过载。卡片展示项目 badge、来源图标、`why_now`、上次更新、风险等级；不直接展示 Raw payload。空态：「目前没有值得打扰你的事情」。

### U02 Chat
消息区、输入框、右侧可折叠 Run Timeline。Demo 回复由真正 Mock Adapter 生成，页面必须标注“离线演示 · 不连接模型”；Hermes 接通后标注连接状态、会话 ID（脱敏）。支持 markdown 安全渲染；不支持 HTML 原样注入。输入发送成功后可见消息和生成的 run id；加载中/取消/超时态不能永转圈。

### U03 Projects
项目磁贴/列表 + 项目详情：项目目的/当前 milestone/最近事件/主动建议/Artifacts。内置 `Project Atlas` 与 `Project Beacon` 两个纯合成项目。全局项目切换需影响 Card 数据查询范围；不能仅靠前端隐藏跨项目数据。

### U04 Activity & Run Detail
任务行含执行类型、发起时间、状态、duration、验证 verdict；点击展示状态时间线、每一步工具名称（不得包含 secret 参数）、artifact link、失败类别、重试策略。`awaiting_approval` 需要显式批准面板且默认“拒绝”。

### U05 Settings
环境状态（Demo / Real connector 状态）；数据源开关默认 OFF；quiet hours 默认 22:00–08:00（用户可修改）；max cards/day 默认 3；本地数据位置；清空**专用 Demo DB**按钮明确二次确认。绝不能一键删除 user vault。

## UI 状态矩阵
| 情况 | UI |
|---|---|
| 第一次运行 | 自动初始化合成样本+欢迎说明 |
| 无候选 | 平和空态、不制造虚假任务 |
| 过期卡 | 可看证据、不能执行，提示重扫 |
| 执行中 | 实时步骤条、取消操作；不伪造成功 |
| 需审批 | 高亮作用目标、影响范围、参数散列、有效期 |
| 失败 | 解释原因、可复制 trace id、提供安全的重试方式 |
| 验证未知 | amber “尚未确认”，不得绿色 success |
| API 断开 | 明显退回 Demo 或 error，不假装接入 Hermes |

## 组件结构
`AppShell`, `NavRail`, `NowBrief`, `ActionCard`, `EvidenceDrawer`, `ApprovalSheet`, `TaskTimeline`, `PanelRenderer`, `ProjectSwitcher`, `ConnectionBadge`, `EmptyState`, `ErrorBoundary`, `ConfirmDialog`, `CommandInput`。

## 交互动效
仅 opacity/transform，160–220ms ease-out；系统 prefers-reduced-motion 则禁用。点击卡片先入 `queued`，后端返回明确 task id 才进入处理；点击重复禁止双重执行，刷新后继续一致。通知不是强弹窗，默认无桌面推送。

## 无障碍与测试
页面标题有 H1、按钮使用可访问名称、颜色对比足够、焦点样式明确；按钮禁用说明原因；截图覆盖 Home/Chat/Projects/Activity/Settings 的空态、常态、执行态、失败态；E2E 验证键盘操作与窄屏 1280×800。

## 开发次序
先数据契约→操作功能→布局及组件→视觉细节。不可先实现全部静态页面再补业务逻辑，否则会让用户明早只能看 Demo 壳。
