## 2. 威胁模型

| 威胁 / 触发 | 防护设计 | 最小负例证据 |
|---|---|---|
| 跨项目/线程串线（现有无过滤路径） | 服务端 project/source 授权和绑定，禁止全局 listCards 混入线程；切换时取消并隔离响应 | 两个隔离项目独特标记，直接 API、切换、重启后均不泄露（N07/N16/N25） |
| Demo 假完成进入真实模式 | 服务端真实模式关闭旧模拟 action；旧 Demo 明示模拟，不以客户端 `demo` 判安全 | 伪造 action/demo/风险字段、重复提交，覆盖线程、卡片、审批及间接调度，未知/真实模式不调用 executor、不显示真实完成（N11/N12/N22/N30） |
| prompt injection、恶意网页/README | 外部内容作为不可执行数据；模型无执行工具；输出 schema + 引用核验 + 对抗样例 | 网页要求读取密钥/执行命令/篡改权限，记录脱敏阻断且无写入 |
| 私密信息外发 | 显式允许的公开主题与外发范围；本地拒绝敏感路径、密钥、源码；不能确定则 BLOCKED | 无网络请求断言；不能把正则替代人工安全保证（N03） |
| SSRF/跳转/重绑定 | HTTPS 白名单、每跳 DNS/IP 及重定向检查、地址限制、响应大小/超时；禁内网与元数据 | 模拟 loopback、私网、跳转、重绑定、过量响应；调用计数为零/终止 |
| 费用超限和重复调用 | 授权版本+原子配额预留、单任务幂等、租约/崩溃 outcome_unknown，不盲重试 | 并发耗尽/中断/重启不重复付费、不越额度（N04/N13） |
| 权限撤销/TOCTOU | 每次出站前、结果提交前复核项目、来源、policyVersion；取消尽力中止并诚实标注在途 | 授权在排队/发送中撤销，后续无请求；在途结果不声称可撤回 |
| 模型幻觉/过期或伪造引用 | 不可信输出独立 schema/project 和按类型的来源版本/可用性检查，事实/推断拆分，质量仍由人评 | 未知 URL、跨项目和旧 epoch withheld，不因格式合格宣称真实（N05–N08） |
| 项目删除/重建、崩溃造成悬空引用 | deletion journal、tombstone、幂等分步恢复；按来源类型标记 epoch 或版本失效 | 每个中断点重启，删除期间拒绝读写；历史引用不自动重绑定 |
| 高频主动打扰/投递丢失 | GET 只读，独立幂等 claim/presented 与反馈，持久 dedupe、冷却，用户编辑不抢焦点 | 并发多页/超时/ack 丢失/崩溃可恢复，用户搁置后不重发；承认显示后 ack 前崩溃可能重复（N09/N10/N15/N23/N24/N28） |
| 周期扫描越权或空耗 | 主题持久授权、范围/频率/额度/有效期和版本逐次核验；公开元数据优先，内容不变不调用模型 | 无 Git 变化可在授权周期内发现新公开来源；撤销/过期/超预算无请求，无新资料无模型调用（N26/N27） |
| 不同来源错误复用身份 | Observer epoch、公开资料 URL/哈希及用户决定版本分别校验，不互相伪造 | 一类失效不会无故冻结其他类型；跨项目引用拒绝，无法解析 withheld（N07/N29） |
| 本地服务被其他网页利用 | loopback、session、Origin/CSRF、严格 Zod；失败关闭 | 直接跨源/缺 CSRF/伪造项目请求均拒绝，审计脱敏 |
| 旧来源未观察误导 | freshness 六态、观测覆盖区间和 gap 显示；不由缺失推出结论 | 停止、断网、未知、间隙/陈旧均不能说项目休眠或健康（N08/N17） |

## 4. 待用户审阅的决策与后续授权

1. 先按 G1-A/G1-B/G1-C 独立验收安全、项目经历、观点记忆；先修复旧主动接口隔离与伪完成，再做 G1 观点存储；旧安全 E2E 必须保留语义。历史 UI 布局用例按新合同调整，不靠删除用例变绿。
2. 项目身份采用新增身份 + 明确绑定；新库与三套现有库独立、跨库删除用 journal。实际 migration 的具体表、恢复边界需在 G1 小提交再验。
3. MVP 暂不开放真实执行；单独设计研究/模型授权，原有 Pi 的每次内容确认不因自动化被削弱。首个真实公共入口、允许的持久主题范围与周期、具体模型、每次/每日预算未决定，不预填或私自开户。
4. 真实 H1 的项目、观察范围、公开主题、网络接收方、模型/数据范围、经费和用户人工价值评审需分别明确；目前均不是已授予的自动授权。

请审阅上述具体方案。G0 结论与此审阅不自动授权 G1 开发、远端推送、合并、付费或真实数据外发；具体阶段需由用户明确发起。G1-A → G1-B → G1-C 依次通过、整个 G1 通过前不能开始 G2，之后同样遵守阶段门禁。
