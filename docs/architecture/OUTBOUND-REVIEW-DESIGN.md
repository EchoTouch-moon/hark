# 实际请求审阅与发送边界（设计与实现状态）

## 目标和当前状态

每一次模型调用都必须让用户审阅实际发出的完整请求正文、接收地址、模型、调用限制和本次实际来源。项目目录读取授权和项目模型权限不能替代该次批准。工具读取新资料后形成的新请求也必须重新审阅。

当前已实现的部分是隔离基础：Host 可以截取 SDK 最终序列化正文并交给受信 dispatch；Host 与 Native 已在显式合成模式中通过 IPC 完成审阅、批准、拒绝及取消，实验性批准账本和数据库锁边界尚未接入实际发送。独立发送器已经在本地合成 TLS 服务中测试，功能默认关闭。`model_transport_available` 仍为 false；生产 sidecar 未注入真实网络，也不会产生待审事件。任何单项测试通过都不表示真实聊天已接通。

## 最终数据流

1. Host 完成上下文组装，在 HTTP 发送边界截取固定 endpoint 的 POST 正文。Native 不应信任 UI 或模型提供的 endpoint、模型、限制、来源或批准状态。不可将认证头传给审阅界面或写入日志。
2. Native 基于实际正文和可信读取记录形成不可变的待审请求；界面原样展示正文、接收方、模型、限制及逐项来源。完整正文可能包含不可信文件数据，不得作为指令执行。来源须覆盖正文中的历史会话、上下文和工具结果；缺失来源时关闭发送，不能将缺失标为没有来源。
3. 用户批准一次后，持久记录正文 SHA-256、来源快照、授权版本、接收方、模型、限制、运行身份和有效期；禁止把密钥或正文写入审批日志。拒绝、超时或撤销均不得产生发送许可。
4. 在受信 Native 发送器内先持久消费批准，确保崩溃后不重放；随后取得与撤权、暂停、取消相同的数据库写入边界，复核批准绑定、授权、运行状态和当前来源。实际 socket 写入必须在此边界内同步开始，不能在持锁时仅排队 Node 稍后发送。
5. 一旦请求开始，撤销不能收回已发出的字节；它必须阻止后续模型轮次和不再有权提交的结果。HTTP 响应流应在开始发送后释放数据库锁并受取消信号控制；失败或状态未知不得自动重发。

批准时和发送前应以本次已展示的精确字节为基准。磁盘重新读取需沿用受授权的目录身份和越界防护；截断内容的指纹必须明确是实际发出的片段还是原文件，不能混用。外部进程修改文件不能被 SQLite 锁住，因此需要定义读取版本与已审阅快照的关系，不能声称 SQLite 本身原子锁定文件。

## 未完成的接入

- 将完整正文与可信来源从 Host 传给 Native，并解决历史会话、首次开场及上下文中来源的完整追溯。当前实验账本支持普通对话和首次开场；实验发送边界会重新读取指定来源并核对原先读到的字节，但尚不能验证来源列表是否完整，也无法阻止外部进程在核对后修改文件。
- 将 Native/Tauri 的待审、批准、拒绝和取消协议连接 Host 的真实待审事件；审阅等待应有独立时限，不能被当前 60 秒运行期限提前杀死。需对 IPC 大小、文本编码、关闭窗口和重复动作做明确处理。当前 UI 的独立等待上限不能延长尚未改造的 Host 运行期限。
- 将实验 Native HTTP 发送器与批准账本和流式响应桥接起来。当前已对固定 endpoint、TLS、重定向拒绝、分块响应、取消和时限进行隔离测试，未使用真实服务；实验 `consume_and_begin_outbound` 的回调契约依赖调用者：闭包不得排队异步发送或重入 Core；它不能使数据库和网络成为原子事务。DNS/TLS 连接本身也是外部副作用，必须在持久批准及授权复核后进行。
- 明确发送已开始、失败、未知和崩溃恢复的持久状态。已消费但尚未发送、或已发出但响应未知时，不得自动重试。
- `outbound-review` 目前为默认关闭的隔离 feature，启用后数据库升级到 v5，旧版无法打开；上线前需完成兼容、备份和回退设计。现有用户数据库保持 v4。
- 完成真实数据之外的端到端验证：批准/拒绝、完整正文篡改、来源变化、目录和模型撤权、跨连接并发、每轮工具调用、长时间审阅、取消、进程崩溃和流中断。通过后再展示具体请求并由用户决定是否进行真实模型验证。
