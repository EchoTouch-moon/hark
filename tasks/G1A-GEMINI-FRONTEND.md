# G1-A 前端任务 · 交给 Gemini 的工作说明

## 产品与授权

Hearth 的 G0 v0.2 已通过文档审查。G1-A 只建立可信安全基线：修复真实/未知模式中的旧模拟入口呈现、清楚标识 Mock、恢复相关 UI 安全测试，不实现项目记忆、Opinion Engine、主动研究或火焰语义重设计。桌面优先（1280×800、1440×900），延续已有对话空间和火影。

后端由另一位开发者负责：真实及未知模式中旧线程主动建议和执行路径失败关闭；GET proactive 不写入；旧执行/审批 API 的具体返回以其最终合同及测试为准。前端不能把隐藏按钮当作安全控制，也不能由客户端决定执行权限、风险或完成状态。接口暂不可用时诚实显示不可用或静默，无伪造结果、重试风暴或虚假完成。

## 文件责任与协作

- 可修改：`apps/web/src/` 中 G1-A 必要页面/组件/样式/客户端状态；`tests/e2e/runtime-mode.spec.ts`、`tests/e2e/hearth.spec.ts` 中相应 UI 验证及必要的前端专属测试。
- 不修改：`apps/server/`、`packages/`、数据库迁移、安全策略和后端 API；不修改其他人的未完成改动，不重置分支。
- 开始先阅读 `AGENTS.md`、`docs/mvp/00-START-HERE.md`、`docs/mvp/g0/02-contract-and-decisions.md`、`docs/mvp/g0/03-plan-threats-traceability.md`、`docs/mvp/g0/04-ci-and-legacy-route-review.md`；核对当前工作区和后端变更再动手。
- 禁止推送、合并、真实模型/研究调用、修改其他仓库或真实私人数据；不要默认把 Gemini/第三方模型接入应用。

## 必做交互与验收

1. 后端模式加载中、未知、非法或接口失败时前端失败关闭；真实模式和未知模式不显示可触发的旧 Demo 行动。直接访问 `/demo` 同样安全，重试恢复必须经过真实有效的健康状态。覆盖刷新、网络失败与恶意伪造健康返回的界面场景，后端拒绝由服务端测试独立保证。
2. Mock 对话必须向用户**实际可见**地标注离线模拟及“不连接真实模型”，欢迎遮罩、菜单、昼夜、窗口大小和刷新不可让标识永久隐藏；无标识时不得声称真实 AI。修复 CI 中定位到元素但 `hidden` 的问题，不只换定位器。
3. 接受后端返回无主动建议或拒绝旧 action：不出现伪造成功、执行进度、项目状态或跨项目内容；错误保持可理解且不丢草稿。不得创造 G1-B 的临时项目身份/绑定模型。
   当前后端对旧主动建议返回 `suggestion: null`，未知线程返回 404；对旧 action / cards / projects / events / discover / seed / reset 返回 403 `LEGACY_ACTIONS_DISABLED`，包括默认 Demo 运行模式。`GET /api/v1/health` 的 `legacyDemoAvailable` 表示旧演示入口实际可用性；缺失、无效或 false 时均失败关闭，不得只根据 `demoMode` 展示可执行旧操作。真实项目应使用既有 Observer API，而不是旧 Demo 项目接口。历史接口可能返回 `legacyHistoryWithheld: true`；历史原文未删除。特别注意 `apps/web/src/features/chat.ts` 现有的 404、403 或网络失败分支可能回退本地 Mock、生成虚假建议与“已完成”，必须取消这些不安全回退。`threads.ts` 的空列表/异常本地回退也需按真实/未知模式失败关闭。
4. 用新的对话优先结构改写 `runtime-mode.spec.ts` 和 Chat Mock 相关浏览器用例，保留模式隔离、直接 URL、透明标识、真实可见、会话持久、错误恢复和键盘可操作性断言；不得靠 skip、删除断言或伪造 API 返回让 CI 变绿。对尚依赖 G1-B/G4 的旧 UI 用例单独记录，不顺手重写不相关界面。
5. 使用合成/隔离数据做浏览器验证：至少覆盖 1280×800 与 1440×900、真实/未知/无效模式、离线标识可见、欢迎流程、拒绝 action 和无主动建议；保存脱敏截图及实际测试日志，标注 Mock，不能声称真实研究或新 MVP 通过。
6. 汇报修改文件、命令/结果、截图路径、剩余失败及与后端合同的兼容性；仅在明确协作方式允许时提交本地 commit。不要推送、合并或自行扩大任务。
